# Translation Generation and Recovery Contract: Spec 019

**Governance**: [Constitution v2.1.0](../../../.specify/memory/constitution.md) at original design; synchronized 2026-11-10 with [Constitution v3.0.0](../../../.specify/memory/constitution.md). Derivatives are the two non-source locales of each tour's fixed canonical source locale ([spec.md Amendment Record](../spec.md)).
**Scope**: Internal TourContentTranslator/job/state boundary; no public provider endpoint.
**Status**: Synchronized 2026-11-14 to the [EGM-003 technical design v3](../../../docs/designs/supplier-portal-egm003-governance-v3.md) and its [execution file/test manifest](../../../docs/designs/supplier-portal-egm003-execution-plan.md). No schema, migration, code or test has been written; EGM-003 remains open.

## Request Boundary

Reuse TourContentTranslator and GeminiTourTranslator. A new job carries tourId, one requested derived locale (a non-source locale of that tour), sourceHash and generationEpoch; legacy jobs may deserialize with a null epoch and must perform no writes. Never carry credentials, provider responses, private partner/booking/payment fields or raw prompts. The worker loads the current whitelisted canonical source of the tour. Translate nonempty source strings by stable paths; reconstruct into the source shape so numeric day/duration, nulls and list ordering stay unchanged.

The backend sends the existing structured JSON generateContent request with backend-only configured model/key. Prompt input is data, not instructions. Exact expected keys must return once each as nonblank strings; unknown/missing/duplicate keys or invalid lengths reject the result. Validate every source-field and itinerary bound after reconstruction, including numeric fields preserved from source. [Gemini structured outputs](https://ai.google.dev/gemini-api/docs/generate-content/structured-output) supports structured JSON but does not replace application value validation.

Specific media alt text remains source-locale-specific accessibility text with actual alt_locale; it does not add a per-photo translation or AI-caption request.

## Revision and Atomic Completion

1. Persist the canonical source and desired derived-locale states in the source transaction. Lock Tour, then the source translation, then derived states in platform order. Compute normalized current hash; unchanged source is a no-op.
2. Dispatch after commit to an asynchronous Redis worker. Source HTTP success is independent of provider completion and of a recoverable post-commit queue-dispatch failure.
3. Worker prechecks existence, hash and epoch. Superseded, deleted or missing-source jobs exit without a content write. Perform provider HTTP outside database locks.
4. On completion, take the same lock order and recompute source hash and epoch. Only a matching current desired hash **and** epoch can be applied. If matching ready content already exists, derivative writing is a no-op; do not replace it merely because another worker produced different wording. Precheck matching-ready work before the provider call and allow idempotent projection refresh without regeneration, repairing a prior index-dispatch failure after ready commit.
5. Atomically store one derived tour/locale row, ready status and translated_hash. Clear sanitized error, commit, then dispatch index refresh and relevant cache invalidation.
6. Failure writes only when the same desired hash and epoch are still current and not ready. A late failure cannot demote ready/newer content. Existing old derivative remains retained but not current.

Use the existing unique tour/locale constraints and database serialization for correctness. Job dedup can save provider cost but is not a substitute for revision checks, and must not suppress a newer desired hash or failed-current retry indefinitely.

## Failure Classification and Limits

| Outcome | Behavior |
|---|---|
| Missing/invalid config or unsupported requested locale | Sanitized permanent category; source remains saved |
| HTTP 408/429/5xx or network timeout | Retry current work with bounded attempts/backoff |
| Other rejected response, blocked/incomplete output, malformed JSON/shape/value | Sanitized permanent failure; no invalid derivative write |
| Retry exhaustion | Failed for matching current hash and generation epoch only; never overwrite current ready state |
| Superseded work or failure after ready | No derivative/state mutation; matching-ready retry may refresh projections without provider work |

Retain four attempts and backoff5/15/60 seconds. Design target: provider timeout40 seconds, job timeout60, Redis retry-after90; worker timeout must not exceed the job's effective timeout, and retry-after must remain greater. Validate deployed values before release rather than assume docker defaults prove them. Automated tests use fake provider/queue; test processes must not inherit real provider credentials or make network calls.

## Recovery and Projection Freshness

Extend existing `tours:queue-translations --after-id=0 --limit=100` (limit1-500) to reconcile desired current states, including pending work whose dispatch was lost. Requeue only current unfinished revisions. Add optional `--refresh-ready` to schedule idempotent index/cache refresh for matching-ready tours without provider calls or derivative writes, covering lost projection dispatch after a ready commit. Repeated reconciliation may enqueue duplicate work, which completion safely handles; do not claim exactly-once provider calls. Index refresh loads current source/state rather than replaying translated strings captured by an older job.

Corrective adoption uses `tours:adopt-itineraries` and then the same source/hash/state service. Dry-run enqueues nothing. Current success/source changes schedule projections after commit. Do not cache a derivative as current when its hash no longer matches; detail reload selects live current source/state, while existing discovery cache/index policy remains explicit.

Monitor queue lag, unfinished/failed state counts, sanitized categories and source-fallback rate without logging prompts, raw responses or secrets. A live staging smoke uses only a configured available model and provisioned backend secret; it is not mandatory for fake-based automated tests and has not been executed in planning.

## Required Interleavings

Real PostgreSQL tests must demonstrate old completion versus newer source, two completions for the same hash, terminal failure after ready, source transaction rollback, queue failure after commit/reconciliation, changed source content during legacy adoption, and concurrent source edits using a consistent lock order. Provider fake barriers/independent DB connections control the ordering; sequential hash assertions alone are insufficient evidence of row-lock correctness.

## Revision-Bound Generation (EGM-003 owner decision, 2026-11-14)

Gemini derivatives are never manually edited. The generation job is the only writer of a derivative row, and it is bound to the tour's **canonical generation epoch** and source hash. This section was synchronized on 2026-11-14 to the [EGM-003 technical design v3](../../../docs/designs/supplier-portal-egm003-governance-v3.md) and its [execution file/test manifest](../../../docs/designs/supplier-portal-egm003-execution-plan.md). There is **no** publication epoch in this contract: the approved-revision pointer changes on every first/re-publication, but the generation identity is the source hash plus the generation epoch.

**Job payload.** `GenerateTourTranslationJob(tourId, locale, sourceHash, generationEpoch)`. The plan tuple produced by `planSourceDispatches()` carries the tour's current generation epoch. The epoch is the binding identity; the approved-revision pointer is not a derivative-write fence, because a re-publication may establish a new approved revision ID for equal source text while in-flight work for identical canonical content stays valid.

**Guards before any write.** The tour exists; the locale is a derivative locale of the current source locale; the freshly recomputed source hash equals the job's `sourceHash`; the derivative state's `source_hash` equals the job's `sourceHash`; the derivative state's `generation_epoch` equals the job's epoch; the tour's `generation_epoch` equals the job's epoch; the desired-state identity still matches; and the derivative is not already current. A job whose epoch is absent — every job dispatched before this change — is refused, because the tour's epoch is a non-null integer from the first release that carries the column. A job whose epoch is older than the tour's is refused. **Only** the current source hash **and** the current generation epoch may change derivative rows or states.

The guards are executed twice: once as a preflight before provider work, and again under the Tour lock immediately after the provider I/O, so a completion cannot apply against a moved identity. Failure callbacks use the same identity fence and cannot turn current ready work into failed.

**Epoch rules.** The tour's generation epoch advances when the canonical source hash changes, including active option source text: a partner save on a never-published tour, or an approval that changes the canonical text. It also advances on an explicit authorized force-regeneration, even with equal text, to fence older work. The advance and the derivative-state re-arm happen in the same transaction. A media-only or presentation-only approval leaves the canonical hash and therefore the epoch unchanged, so no regeneration is dispatched, while the public content version still advances and in-flight work for identical canonical content remains valid. An A→B→A content cycle produces a third, distinct epoch, so the earlier A-derivative is no longer current and is regenerated — a content hash alone cannot express this. A pre-publication job for unchanged content stays valid across the first publication, because publication does not change the canonical content and therefore does not advance the epoch.

**Desired-state rules.** Matching hash+epoch with a ready state and a real derivative row preserves the derivative; matching pending or stale work allows a duplicate requeue for recovery; a failed state is retried by reconciliation; a mismatching epoch or hash overwrites the desired identity, marks the stored derivative stale (or a missing derivative pending) and enqueues current work. A matching ready state without a row is unfinished, not ready. When one state epoch is used, advancing the desired identity MUST clear the translated currency before marking the state pending or stale. Existing successful derivatives are kept for fallback and history and are never labelled current by hash alone. Reconciliation replaces orphan epoch-less or stale pending jobs rather than preserving an unrecoverable pending state.

**Leak rules.** The job reads only the materialized source translation row and the live options; it never reads a candidate revision payload. Candidate content therefore never reaches the provider, a derivative row, a derivative state row, the search index, or a public projection. No credential, provider body, prompt, or private partner, booking, or payment field is carried by the job.

**After an approval.** When the approval changes the canonical source text, it materializes the canonical source row and the option authored texts, so the recomputed source hash changes. Both derivative locales are then marked stale (row present) or pending (no row) with the new desired hash and epoch and dispatched after commit. A media-only or presentation-only approval changes neither the hash nor the epoch, so no regeneration is dispatched. While a derivative is not ready the public page serves the newly approved canonical source with the existing localized notice; derivative readiness never blocks the approval, and the approval never waits for generation. Missing, pending, stale or failed derivatives never block an eligible approval, and the public fallback is the newly approved source with a localized source-language notice.

**Retirement of the legacy field engine.** The English-only field engine with its manual-override semantics (`AutoTranslationService`, `Tour::supportsFieldTranslation()`) no longer applies to tours: `supportsFieldTranslation()` is false for every tour, the Filament actions that invoked it are removed from the Tour edit page, and the replacement is a read-only derivative status plus a dedicated regeneration action that re-dispatches this revision-bound job. Legacy tour field jobs are refused both before provider work and immediately before any save under a fresh Tour lock; a legacy job with a null epoch performs **no** success or failure write, and reconciliation queues replacements instead of preserving an unrecoverable pending state. Published itinerary adoption is refused or reported and never silently writes canonical published content; non-published adoption keeps its existing validation and epoch planning. Demo web generation remains refused. The CMS and blog use of that service is unchanged.

**Activation.** Retiring the engine is part of the single coordinated EGM-003 cutover, not a separate drain: production enters maintenance for partner/administrator writes, queue producers and schedulers stop, old workers gracefully finish their current jobs and provider calls and then exit (bounded by the configured timeout, with process exit verified), the complete new build and the additive schema are deployed, baselines are captured and current derivative states reconciled, and only new workers are restarted. The queue is **not** claimed to empty while the workers are stopped; queued or delayed old jobs may remain, and the new workers safely no-op their null epoch while reconciliation queues replacements. The supported rollback is a compatible build that retains the governance guards, with proposal/correction/approval writes disabled if necessary. No live provider smoke is claimed by fake-provider tests.
