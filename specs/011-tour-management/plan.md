# Implementation Plan: Tour Management — Traveler Dashboard, Bookings, Profile & Wishlists

**Branch**: `011-tour-management` | **Date**: 2026-05-20 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/011-tour-management/spec.md`

## Summary

Extend the Bookly public frontend (built in Phase 1 / spec 010) with authenticated traveler features: a bookings dashboard with status filters, booking detail & receipt view, self-service cancellation flow, profile & preferences management, wishlist save/remove with optimistic UI, my-reviews listing, and an authenticated global header dropdown. All pages are auth-guarded, responsive, localized (EN/ES/IT), and SEO-ready.

## Technical Context

**Language/Version**: TypeScript 5.x, Next.js 16 (App Router)  
**Primary Dependencies**: React 19, Tailwind CSS, existing auth/API client from Phase 1 (spec 010)  
**Storage**: N/A — frontend consumes Laravel API exclusively  
**Testing**: Jest, React Testing Library, Playwright (E2E)  
**Target Platform**: Web (Chrome, Safari, Firefox, Edge), responsive mobile-first  
**Project Type**: web-application (frontend)  
**Performance Goals**: Dashboard render < 2s; wishlist toggle visual feedback < 100ms; Lighthouse Performance ≥ 90  
**Constraints**: WCAG 2.1 AA; mobile breakpoints 390px / 780px / 1280px; 3 locales (EN, ES, IT)  
**Scale/Scope**: 7 new routes, ~15–20 new components, 5 API domains, auth-guarded
