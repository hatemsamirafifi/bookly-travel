# Data Model: Tour Management — Traveler Entities

## Overview

This document defines the frontend TypeScript types and UI-facing entities for authenticated traveler features. These types mirror the API responses expected from the Laravel backend.

---

## 1. Booking (Dashboard + Detail)

```typescript
interface Booking {
  id: string;
  reference: string;           // e.g., "BOK-2026-ABC123"
  status: BookingStatus;       // "confirmed" | "completed" | "cancelled"
  tour: {
    id: string;
    name: string;
    coverImage: string;
    slug: string;
    location: string;
    duration: string;          // e.g., "4 hours"
    meetingPoint: string;
    inclusions: string[];
  };
  bookingDate: string;         // ISO 8601
  tourDate: string;            // ISO 8601 date
  tourTime: string;            // e.g., "09:00"
  participants: number;
  pricePerPerson: number;      // in cents (minor units)
  totalAmount: number;         // in cents
  specialRequests?: string;
  cancellationDate?: string;   // ISO 8601, present if cancelled
  createdAt: string;
}

type BookingStatus = 'confirmed' | 'completed' | 'cancelled';
```

### Validation Rules
- `reference` is read-only, generated by backend.
- `status` transitions: `confirmed` → `cancelled` (traveler-initiated); `confirmed` → `completed` (backend, post-tour).
- Cancellation eligibility: `status === 'confirmed'` AND `tourDate` is in the future.
- If `tourDate` is within 24h, UI must show late-cancellation warning.

## 2. Payment Receipt

```typescript
interface PaymentReceipt {
  bookingId: string;
  status: PaymentStatus;       // "paid" | "refunded" | "pending"
  amount: number;              // in cents
  transactionDate: string;     // ISO 8601
  method: {
    type: 'card' | 'paypal' | 'bank_transfer';
    last4?: string;            // e.g., "4242" for cards
    brand?: string;            // e.g., "visa"
  };
}

type PaymentStatus = 'paid' | 'refunded' | 'pending';
```

### Notes
- Receipt is read-only; mutation happens via backend payment webhooks.
- Display currency formatting according to traveler's preferred currency (from profile).

## 3. Traveler Profile

```typescript
interface TravelerProfile {
  id: string;
  firstName: string;
  lastName: string;
  email: string;               // read-only
  phone?: string;
  preferredLanguage: Locale;   // "en" | "es" | "it"
  preferredCurrency: string;   // e.g., "USD", "EUR"
  marketingEmails: boolean;
  avatarUrl?: string;
}

type Locale = 'en' | 'es' | 'it';
```

### Validation Rules
- `email` is read-only; changes require email verification flow (out of scope).
- `phone`: optional, must match E.164 or a client-side regex if backend doesn't validate format.
- `preferredLanguage`: when updated, the UI must trigger a locale reload (`router.push` with new `[locale]`).

## 4. Password Change

```typescript
interface PasswordChangePayload {
  currentPassword: string;
  newPassword: string;
  newPasswordConfirmation: string;
}
```

### Validation Rules
- `newPassword` minimum 8 characters, at least one uppercase, one lowercase, one digit.
- `newPassword` must match `newPasswordConfirmation`.
- Client-side validation before submission; server-side validation is authoritative.

## 5. Wishlist Item

```typescript
interface WishlistItem {
  id: string;                  // wishlist entry ID
  tour: {
    id: string;
    name: string;
    coverImage: string;
    slug: string;
    price: number;             // in cents
    rating: number;            // 0–5, 1 decimal
    reviewCount: number;
    location: string;
    duration: string;
    isAvailable: boolean;      // false if unpublished / sold out
  };
  addedAt: string;             // ISO 8601
}
```

### Notes
- If `tour.isAvailable` is false, card shows "No longer available" overlay and remove button.
- Wishlist is persisted server-side; fetched on login.

## 6. Review Record

```typescript
interface ReviewRecord {
  id: string;

    id: string;
    name: string;
    slug: string;
  };
  rating: number;              // 1–5 integer
  text: string;
  submittedAt: string;         // ISO 8601
}
```

### Notes
- Read-only listing in Tour Management scope. Review submission remains in spec 009 scope.
- Card links to tour detail page `/{locale}/tours/{slug}`.
