# API Contract: POST /api/public/auth/login

## Endpoint

```
POST /api/public/auth/login
```

## Description

Authenticates a traveler using email and password. Returns a Sanctum personal access token and user data on success. Implements brute-force protection with escalating lockout tiers.

## Middleware

- `throttle:auth` — 10 requests per minute per IP address

## Request

### Headers

| Header | Value | Required |
|--------|-------|----------|
| `Content-Type` | `application/json` | Yes |
| `Accept` | `application/json` | Yes |

### Body (application/json)

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `email` | string | required, email format | Traveler's email address (normalized: trimmed, lowercase) |
| `password` | string | required, min 1 character | Traveler's password |

### Example

```json
{
  "email": "jane@example.com",
  "password": "MyPassword1"
}
```

## Responses

### 200 OK — Successful Authentication

```json
{
  "data": {
    "user": {
      "id": 1,
      "name": "Jane Doe",
      "email": "jane@example.com",
      "role": "traveler",
      "locale": "en",
      "email_verified": true,
      "created_at": "2026-04-25T12:00:00Z",
      "last_login_at": "2026-04-25T14:30:00Z"
    },
    "token": "1|abcdef1234567890..."
  }
}
```

**Fields**:
- `data.user`: `UserResource` — full user profile with updated `last_login_at`
- `data.token`: Plain-text Sanctum token (displayed once)

**Side effects**:
- `last_login_at` updated to current timestamp
- `failed_login_count` reset to 0
- `locked_until` set to null
- `TravelerLoggedIn` event dispatched → `LogAuthEvent` writes `login_success` to `auth_audit_logs`

---

### 422 Unprocessable Entity — Validation or Credential Failure

There are **two distinct 422 response shapes** depending on the failure type:

**Shape A — Form Request validation failure** (empty or malformed fields):
```json
{
  "message": "The email field is required.",
  "errors": {
    "email": ["The email field is required."],
    "password": ["The password field is required."]
  }
}
```

**Shape B — Credential failure** (wrong email, wrong password, or no password):
```json
{
  "code": "invalid_credentials",
  "message": "Invalid email or password."
}
```

**Returned for**:
- **Shape A**: Empty email or password (server-side Form Request validation fails)
- **Shape B**: Email does not exist in the system, password is incorrect, or account has no password (guest conversion incomplete)

**Security**: The credential failure message (Shape B) is **identical** for all failure cases to prevent email enumeration. Shape A does NOT increment `failed_login_count` or trigger brute-force tracking — only Shape B does.

**Side effects (Shape B only)**:
- `failed_login_count` incremented by 1
- `LoginFailed` event dispatched → `LogAuthEvent` writes `login_failed` to `auth_audit_logs`
- If `failed_login_count` reaches 5, `AccountLockedOut` event dispatched → lockout applied

---

### 423 Locked — Account Lockout Active

```json
{
  "code": "account_locked",
  "message": "Too many failed attempts. Please try again later."
}
```

**Returned when**:
- `locked_until` is set and is in the future
- Even correct credentials are rejected while locked

**Side effects**:
- `LoginFailed` event dispatched (optional, per spec edge case discussion)
- No change to `failed_login_count` or `locked_until`

---

### 429 Too Many Requests — Rate Limit Exceeded

```json
{
  "message": "Too many attempts. Please try again in 59 seconds."
}
```

**Returned when**:
- IP address exceeds 10 requests per minute on auth endpoints

**Note**: This response is generated by Laravel's built-in `throttle:auth` middleware, not by `LoginController`. The response format and message are controlled by Laravel and do **not** include a structured `code` field. The exact wording and `Retry-After` header value depend on the throttle configuration.

**Headers**:
- `Retry-After`: Seconds until the limit resets

## Error Codes

| HTTP Status | Error Code | Meaning |
|-------------|------------|---------|
| 200 | — | Success |
| 422 | — | Validation errors (Shape A: empty or malformed fields) |
| 422 | `invalid_credentials` | Authentication failure (Shape B: wrong credentials or unknown email) |
| 423 | `account_locked` | Brute-force lockout active |
| 429 | `rate_limited`¹ | IP-based throttle triggered (Laravel middleware) |

> ¹ **429 Note**: The `rate_limited` label identifies the condition, but the actual response body generated by Laravel's throttle middleware does **not** contain a structured `code` field — only a `message` string and `Retry-After` header.

## State Diagram

```
Request Received
    │
    ▼
Throttle Check (IP) ──429──→ Exit
    │
    ▼
Validate Input (Form Request) ──422──→ Exit
    │
    ▼
Normalize Email (trim + lowercase)
    │
    ▼
Find User by Email
    │
    ├── Not Found ──422──→ Exit
    │
    ▼
Check Lockout (locked_until > now?)
    │
    ├── Yes ──423──→ Exit
    │
    ▼
Verify Password (Hash::check)
    │
    ├── Invalid ──422──→ Exit
    │   (increment failed_login_count)
    │   (dispatch LoginFailed)
    │   (check if count == 5 → lockout)
    │
    ▼
Valid
    │
    ▼
Reset failed_login_count = 0
Clear locked_until = null
Update last_login_at = now
Create Sanctum token
Dispatch TravelerLoggedIn
Return 200 + user + token
```
