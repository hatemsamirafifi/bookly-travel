## Overview

Defines marketplace HTTP route methods and middleware for public, partner, and admin surfaces. Laravel mounts these files under `/api/public`, `/api/partner`, and `/api/admin`.

## Interface

- The public surface includes authentication and partner invitation flows, tour discovery, sitemap, booking creation, Stripe webhooks, voucher verification, reviews, traveler account actions, blog, and static pages. [public.php](./public.php#L48), [public.php](./public.php#L102), [public.php](./public.php#L136), [public.php](./public.php#L169), [public.php](./public.php#L194), [public.php](./public.php#L231), [public.php](./public.php#L250)
- The partner surface includes signed uploads, editor media, tour drafts and publishing workflow, pricing, availability, bookings, review responses, analytics, onboarding, notifications, and Stripe Connect. [partner.php](./partner.php#L27), [partner.php](./partner.php#L41), [partner.php](./partner.php#L72), [partner.php](./partner.php#L103), [partner.php](./partner.php#L122)
- The admin API exposes booking audits, financial ledger retrieval, and review moderation. [admin.php](./admin.php#L16)

### Endpoint index

Each row lists the registered route middleware after the shared API group. Laravel registers HEAD alongside GET. Method-specific checks in middleware or handlers still apply. Handler and validation links point to the implementation.

- Sanctum routes require authentication. The API exception renderer returns JSON 401 for an unauthenticated request. Admin role or permission failure returns JSON 403. [Exception renderer](../../../backend/bootstrap/app.php#L69) · [Role check](../../../backend/app/Http/Middleware/RoleMiddleware.php#L11) · [Permission check](../../../backend/app/Http/Middleware/AdminPermissionMiddleware.php#L14).
- The partner gate requires the partner token ability and a corresponding partner record, or returns 404. Active approved partners and legacy active complete partners pass. Other partners can reach the middleware allowlist, including GET tour routes. The remaining operations return 403 with ONBOARDING_STATUS_BLOCKED. [Partner gate](../../../backend/app/Domains/Partner/Middleware/PartnerRoleMiddleware.php#L11).
- Deterministic payment confirmation is registered in local and testing. The controller checks the configured gateway. Session restoration at GET /api/public/auth/me uses auth:sanctum and throttle:traveler. [Conditional payment route](./public.php#L153) · [Session restoration](./public.php#L82).

### Registered-route cross-check

The route manifest was captured with `php artisan route:list --json --path=api` and contains 102 rows: 52 public, 44 partner, and 6 admin, matching the three source files one-to-one on method, URI, handler, and middleware. Laravel reports `GET|HEAD` for each registered GET. This document lists the method the handler serves, with HEAD implied.

### Shared envelopes and rate limits

- The exception renderer returns JSON for `api/*` requests. It returns 401 `{message:"Unauthenticated."}` for missing or invalid Sanctum tokens; 404 exceptions render `{message:"Not found."}`. Explicit controller responses can carry their own message; status ≥ 500 renders the generic `An unexpected error occurred. Please try again later.`; validation failures keep the Laravel `{message, errors}` shape. [Exception renderer](../../app/../bootstrap/app.php#L69).
- Limiter definitions in [AppServiceProvider](../../app/Providers/AppServiceProvider.php#L122): `throttle:auth` normally allows 10/min per IP, `throttle:traveler` 120/min per user, `throttle:booking.create` 10/min per user with a custom 429 body (`{message, retry_after}` + `Retry-After`), `throttle:booking.get` 120/min per user, `throttle:reviews` 10/hour per user, `throttle:verify` 60/min per IP, `throttle:blog` and `throttle:blog_detail` 120/min per IP. Local and opted-in browser test environments can raise the auth, traveler and booking-read limits. The search surface uses [RateLimitSearchMiddleware](../../app/Http/Middleware/RateLimitSearchMiddleware.php#L21), which emits contract 429 bodies with `X-RateLimit-*` headers: search 60/min, detail 120/min, listing 120/min, homepage 120/min, sitemap 10/min.
- Booking UUID rule: the `Idempotency-Key` header on `POST /api/public/bookings` must match the 8-4-4-12 hexadecimal UUID shape. The regex checks shape only, so the checkout-generated v4 keys and any v1 keys are both accepted. Checkout generates its key and sends it with the request. [Key check](../../app/Domains/Booking/Controllers/Public/BookingController.php#L29).
- `partner` controllers receive the partner identity as the `partner_id` request attribute injected by the partner gate; every tour, pricing, and availability lookup is scoped through it. Cross-partner resource reads surface as 404 on this surface, not 403. [Partner gate](../../app/Domains/Partner/Middleware/PartnerRoleMiddleware.php#L11).

### Partner tours, pricing, and uploads contracts

- **Tour list and detail.** `GET /api/partner/tours` accepts optional `status` (draft, pending_review, published, rejected, archived) and `per_page` 1..100, returns 200 `{data, meta{current_page,last_page,per_page,total}}` scoped by the injected partner id with archived tours excluded by default. `GET /api/partner/tours/{id}` requires the tour to belong to the partner — cross-partner and unknown ids both abort 404, never 403 — and returns 200 with the full detail payload including translations, media, pricing tiers, availability, options, and a `translation_statuses` map with provider/job internals stripped. [Ownership](../../app/Domains/Partner/Services/TourService.php#L43) · [Detail builder](../../app/Domains/Partner/Services/TourService.php#L471).
- **Tour create and update.** `POST /api/partner/tours` validates `StoreTourRequest` — required category, destination, duration value and unit, difficulty, localized source fields (`title` max 120, `description` 100..5000, lists max 30 items of 500 chars), itinerary days 1..30, media max 20 with URL length checks, options max 20 with title, price amount 1..10,000,000, group size, start time and weekday rules, plus prohibition of platform-managed keys (`status`, `source_hash`, translation internals). Success is 201 `{data}` with status forced to `draft`; unknown categories abort 422. Side effects: transactional create with ULID-suffixed slug, media sync with cover image promotion, translation rows with sanitized descriptions, and derivative locales queued as translation jobs. `PUT /api/partner/tours/{id}` accepts partial rules with the same prohibitions, applies its FormRequest and scopes the write to the owner, with 404 for a missing or foreign tour, and upserts translations/options — replaced options are retired, never deleted — re-queueing translation jobs only when the source hash changed; success is 200 `{data}`. [Store rules](../../app/Domains/Partner/Requests/StoreTourRequest.php#L47) · [Update service](../../app/Domains/Partner/Services/TourService.php#L184).
- **Draft, submit, archive, delete.** `POST /api/partner/tours/{id}/drafts/save` requires an array `payload` and upserts the opaque draft with `auto_saved_at`, returning the raw draft model; string normalization is skipped for this route per the global middleware config so authored drafts round-trip. `GET /api/partner/tours/{id}/drafts/latest` returns the newest draft (ordered by `auto_saved_at` then id) or the explicit `{message:"No draft found."}` 404. `POST /api/partner/tours/{id}/submit` re-checks the tour content under a lock, returns 422 `Validation failed: …` messages when the authored source-language title or description, at least one pricing tier, or a cover image are missing, and otherwise sets `pending_review` with `submitted_at`, returning 200 `{data, message}`. `POST /api/partner/tours/{id}/archive` and `DELETE /api/partner/tours/{id}` both archive rather than delete: `status` becomes `archived` with `archived_at`, returning 200 messages. [SaveDraft](../../app/Domains/Partner/Controllers/TourController.php#L96) · [Submit](../../app/Domains/Partner/Controllers/TourController.php#L132) · [Archive](../../app/Domains/Partner/Services/TourService.php#L531).
- **Pricing.** `GET /api/partner/tours/{tourId}/pricing` returns 200 with the tour's tier rows under the data key after a partner-scoped 404 lookup. `POST /api/partner/tours/{tourId}/pricing` validates `name` max 100, `price` ≥ 0.01, `min_participants` ≥ 1, optional `max_participants` greater than the minimum; success is 201 `{data, message}` with a plain row insert. `PUT …/{tierId}` and `DELETE …/{tierId}` scope the tier to the owned tour (cross-partner tier ids 404) and return 200 update/delete envelopes; tier deletion does not check bookings. [PricingController](../../app/Domains/Partner/Controllers/PricingController.php#L38).
- **Uploads and media.** `POST /api/partner/uploads/signed-url` validates `file_type` in image/jpeg and image/png plus `file_size` max 5,242,880 and returns 200 `{signed_url, public_url, expires_at}` (15-minute expiry) — the current implementation is a mock pre-signed generator with no database write. `GET /api/partner/hugerte/media` returns 200 `{assets:[{id, url, label, alt}]}` from the partner's own tour media (cover, gallery, image types, latest 50) and aborts 403 when the request carries no partner identity. [UploadController](../../app/Domains/Partner/Controllers/UploadController.php#L12) · [Media controller](../../app/Domains/Partner/Controllers/PartnerHugeRteMediaController.php#L14).

### Partner availability contracts

- The availability index returns HTTP 200 with rules and exceptions under the data key after resolving the partner-owned tour. A missing or foreign tour returns 404. [Index](../../app/Domains/Partner/Controllers/AvailabilityController.php#L30).
- All rule and exception operations first scope the tour to the partner. Update and delete also scope the child record to that tour. A failed lookup returns 404. A failed validation returns 422. Create returns 201 with `data` and `message`, update returns 200 with the same envelope, and delete returns 200 with `message`. These calls directly create, update, or delete the applicable records. [Ownership lookup](../../app/Domains/Partner/Controllers/AvailabilityController.php#L19).
- **Rules.** Creation requires recurring or specific-date rule type, HH:mm start time, start date, and integer capacity ≥ 1. Weekdays are nullable and restricted to integers 0–6. An optional end date must be on or after the start date. Update accepts partial fields, using the controller's validation rules. No idempotency key is handled by these methods. [Create rules](../../app/Domains/Partner/Controllers/AvailabilityController.php#L42) · [Update rules](../../app/Domains/Partner/Controllers/AvailabilityController.php#L72) · [Deletion](../../app/Domains/Partner/Controllers/AvailabilityController.php#L102).
- **Exceptions.** Creation requires a date and type of block, capacity override, or price multiplier. Capacity or multiplier is required for its respective override type. Time and note are nullable. Update accepts partial fields, including nullable capacity and multiplier without the create-only conditional requirements. No idempotency key is handled by these methods. [Create rules](../../app/Domains/Partner/Controllers/AvailabilityController.php#L120) · [Update rules](../../app/Domains/Partner/Controllers/AvailabilityController.php#L153) · [Deletion](../../app/Domains/Partner/Controllers/AvailabilityController.php#L182).
